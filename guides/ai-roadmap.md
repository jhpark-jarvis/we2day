## 서비스 안에서 코스 작성

메인 일정 화면에서 **위투 AI 아이콘**을 엽니다. 일정(날짜·선택 시간대), 이동(지역·수단), 활동(선택 순서·선택 예산·추가 조건)을 입력하고 요약을 확인합니다. **코스 생성**을 누르기 전에는 AI를 호출하지 않습니다. 날짜가 미정이면 **후보 검색**으로 장소부터 찾으며, **바로 대화**로 시작할 수도 있습니다. **초안 저장**을 누르면 기존 플랜 목록에 저장됩니다. 저장한 초안을 열어 장소를 검색하고, 내용을 확인한 후 별도로 확정하면 달력에 반영됩니다.

대화는 작성자 전용 기록으로 저장됩니다. 코스를 달력에 반영하려면 초안 저장과 확정을 별도로 진행하세요. AI는 대화 중 네이버에서 장소 후보를 검색합니다. 서버가 제안의 시간 순서·중복·장소 누락을 검사합니다. **저장한 장소**에서 고른 자주 가는 곳·위시만 AI에 전달하며, 검색 후보의 **선택** 버튼으로 코스에 반영할 수 있습니다. 기존 일정·계정·사진·개인 일정은 자동 조회하지 않습니다. 최근 대화·현재 조건/제안·실행한 도구의 최소 결과를 Cloudflare로 전송합니다. AI가 자동 저장·확정하거나 기존 일정을 변경하지 않습니다.

날씨가 필요한 대화에는 한국 시/군 단위의 Open-Meteo 예보를 조회합니다. 오늘부터 15일 뒤까지의 도시 대표 지점 예보이며 실제 날씨를 보장하지 않습니다. 키 없는 공개 API는 비상업용 조건이므로 광고·유료 서비스를 도입하면 이용 조건을 다시 검토해야 합니다. 응답에 Open-Meteo·GeoNames 출처를 표시합니다. 장소 검색은 영업시간·영업 중 여부·실제 이동시간을 확인하는 기능이 아닙니다.

입력한 조건은 해당 작성자의 대화에 보관되며 **조건** 요약을 펼쳐 확인할 수 있습니다. 날짜·지역 등 이미 정한 조건은 다시 묻지 않고 후속 대화에서 수정합니다. 입력 중인 값은 전송 전까지 현재 화면에만 남습니다. 전송 오류 시 입력을 유지하며 재시도할 수 있습니다. 활동을 고르면 선택 순서와 개수를 검사하고, **추천**을 고르면 활동 종류도 제안합니다. 입력하지 않은 개별 활동 시간·비용은 미정으로 남습니다. 시간대는 실제 체류·이동시간 계산이 아니며 알려진 활동 시각이 범위 밖일 때 확인 사항을 표시합니다. **시작 시간 14:00**, **종료 시간 19:00**처럼 대화로 시간대를 바꿀 수도 있습니다.

## 정확한 장소와 현재 활동 범위

장소 검색은 정확 이름·업종·주변 검색을 구분합니다. 예를 들어 “서울숲 산책”은 이름 “서울숲”으로 검색하며 활동어를 붙이지 않습니다. NAVER 응답의 이름·주소·분류를 서버에서 대조하고 관련 없는 후보를 제외합니다. 분류는 검사에만 사용하며 공급자 설명·링크·광고 내용은 AI 장소 근거로 전달하지 않습니다.

“먼저 도서관만”, “후보만 보여줘”처럼 명시한 이번 단계의 조건은 대화의 작은 현재 상태에 저장합니다. 모델이 다른 업종 검색을 요청해도 실행하지 않으며, 범위 밖의 새 활동이나 요청한 개수를 넘는 코스는 반영하지 않습니다. 사용자가 다른 활동으로 전환하거나 후보를 직접 선택하면 조건을 갱신합니다. 기존 코스의 장소·활동을 유지하는 수정은 보존합니다.

관련도 검사는 알려진 업종과 명시적인 이름·지역 표현에 기반합니다. 모든 자연어 의도를 완벽하게 이해하지는 못하며 검색 API는 최대 5개 후보만 반환하므로 조건에 맞는 실제 장소도 나타나지 않을 수 있습니다. 결과가 없으면 다른 장소를 지어내는 대신 이름·지역을 확인합니다. 검색은 영업 상태·평점·가격·이동시간의 검증이 아닙니다.

도구 계획 단계와 최종 응답 단계를 분리합니다. 최종 단계에 Pydantic 계약으로 생성한 JSON Schema를 Cloudflare에 전달하고, 반환된 객체를 서버에서 다시 검증합니다. 명시한 날짜는 검색 단계에도 보존하며, 날짜와 선택 장소가 정해진 코스 반영 요청에는 코스 객체와 요청 날짜를 필수로 검증합니다. “코스를 만들었다”는 답변만으로 성공 처리하지 않습니다. 추가 필드·유효하지 않은 날짜·범위 초과 등의 응답은 그대로 저장하지 않습니다. 스키마는 형식을 제한하지만 사실과 의미의 정확도까지 보장하지 않으므로 장소 근거·요청 범위 검사를 함께 적용합니다. 지원하지 않는 응답 형식으로 자동 완화하거나 다른 유료 모델로 전환하지 않습니다.

“양주 덕계 근처로 알아봐줘”처럼 지역을 바꾸거나 “추천된 거야?”, “어디야?”라고 이어 물으면 현재 조건을 기준으로 장소를 확인합니다. 확인 질문은 활동이나 코스 내용을 바꾸지 않습니다. 명확한 후보 조회는 모델 없이 기존 검색 도구를 실행할 수 있으며, 실제로 확인한 대표 장소의 이름·주소를 답합니다. 전체 후보 목록은 별도로 보관하지 않고, 대화에 답한 대표 장소명·주소는 작성자 전용 대화 기록에 남습니다. 실패와 빈 결과는 검색 완료로 표시하지 않습니다. 집·회사 별칭은 주소로 추측하지 않으므로 저장 장소를 직접 체크하거나 검색할 동네를 알려주세요. 선택된 공유 링크만으로 동네를 확인할 수 없을 때도 지역 입력을 안내합니다.

## 현재 대화의 조건·수정

날짜·지역·예산·이동수단과 이번 검색 범위는 대화 안에서 유지합니다. “제목만 조용한 하루로”, “두 번째 활동 시간만 오후 5시로”처럼 명확한 수정은 현재 코스 초안의 지정 항목만 변경합니다. 제목·날짜·전체 예산·이동수단·활동 시간을 지원하며, 대상이나 값이 모호하면 필요한 질문 하나를 합니다. 수정 결과도 초안이며 실제 플랜 저장·확정은 사용자 버튼으로 진행합니다.

“샘플카페는 제외”처럼 장소 이름을 명시하면 현재 대화의 후보·새 제안에서 제외합니다. “샘플카페 제외 취소”나 그 장소를 직접 다시 선택하면 해제할 수 있습니다. 제외 장소는 최근 24개까지, 업종 제외와 진행 중인 확인 질문도 현재 대화에만 보관합니다. 새 대화에 자동 적용되는 장기 취향이 아닙니다. 최근 메시지 일부만 전달되는 경우에도 서버가 현재 조건과 보류한 수정을 유지합니다.

명확한 수정·확인 질문·단일 선택 장소 반영에는 모델을 호출하지 않을 수 있습니다. 실제 모델을 호출하는 요청에는 기존 프로젝트 공통 5초 간격과 제공량·실행 상한을 적용합니다. 장소 검색과 코스 생성은 허용된 읽기 도구와 최종 형식·범위 검사를 거칩니다. 모든 자연어를 이해하는 것은 아니며, 지원하지 않거나 불명확한 수정은 내용을 확인합니다.

개발용 합성 한국어 회귀 사례는 `apps/api/tests/fixtures/ai_dialogue_cases.json`에 있습니다. `uv run --project apps/api pytest apps/api/tests/test_ai_dialogue.py`는 외부 AI를 호출하지 않습니다. 실제 모델 평가는 별도 명시 실행으로만 수행하며, 제어된 도구를 사용하는 대화 평가와 실제 장소 검색 연결 시험을 구분합니다.

## 서버 설정

Supabase에 마이그레이션을 순서대로 적용합니다. 내부 AI의 기본 카운터는 SQL036, 제공량 기준과 연속 호출 제한은 SQL038에서 적용됩니다. API 서버의 비밀 환경 파일에 다음 두 항목을 설정하고 API를 재시작합니다. 브라우저 공개 환경변수로 넣지 않습니다.

```dotenv
WE2DAY_CLOUDFLARE_ACCOUNT_ID=
WE2DAY_CLOUDFLARE_API_TOKEN=
```

Cloudflare Workers AI → Use REST API에서 현재 계정에만 Workers AI Read/Edit 권한을 가진 전용 토큰을 발급합니다. 고정 모델은 `@cf/qwen/qwen3-30b-a3b-fp8`입니다. 기존 FastAPI가 REST API로 호출하므로 별도 Worker·D1·R2나 서비스 이전은 필요 없습니다.

Workers Free는 제공량 소진 시 중단합니다. Workers Paid 사용 시 제공량 초과분이 청구될 수 있으므로 계정의 플랜 상태를 직접 확인하세요. 앱 자체의 하루 50회 제한은 없습니다. Cloudflare Workers Free의 계정별 일일 제공량을 기준으로 중단하며, 대화 길이와 출력량에 따라 가능한 요청 횟수가 달라집니다. 무료 제공량은 UTC 0시(한국 오전 9시)에 초기화됩니다. 모델 호출 요청의 연속 실행을 막는 프로젝트 공통 5초 간격은 서버 재시작 후에도 유지됩니다. 입력은 시스템 지침 포함 24KB, 도구 결과를 포함한 모델 요청은 48KB, 호출당 출력은 최대 2,048토큰입니다. 한 메시지에 모델 최대 3회·장소 검색 최대 4회·날씨 조회 최대 2회, 전체 처리 예산은 85초입니다. 다른 앱의 Cloudflare 사용량까지 통제하지는 않습니다. 공급자 한도·통신 오류 때 자동 재시도나 다른 유료 모델로 전환하지 않습니다. 출력 형식이 맞지 않을 때는 같은 3회 예산 안에서 JSON 완성 단계를 한 번 거칩니다.

## 구성과 한계

브라우저 → 같은 출처의 인증 중계 → FastAPI → DB 사용량 예약 → Workers AI 순서입니다. 답변의 JSON·플랜 형식을 검증한 뒤 화면에 표시합니다. 일반 서버 로그에는 대화·키 원문을 기록하지 않습니다. 작성자 전용 DB에는 성공한 질문·답변·제안과 지침 버전을 보관하고, 별도로 날짜별 호출 횟수를 기록합니다. 초안 저장은 기존 사용자 권한과 요청 재시도 계약을 사용합니다.

대화 횟수로 세션을 차단하지 않습니다. 최근 최대 11개 메시지와 현재 코스를 입력 상한 안에서 전달하며, 오래된 대화는 화면에 남아 있어도 모델 입력에서 제외될 수 있습니다. 현재 대화에서 정한 날짜·지역·활동 순서는 작은 조건 데이터로 별도 전달합니다. 장기 취향 기억이나 RAG는 제공하지 않습니다. 완성된 답변을 검증 후 표시합니다. 토큰 스트리밍·장기 대화 요약·기존 플랜 자동 편집은 제공하지 않습니다. 향후 필요성과 데이터 정책을 정한 뒤 검토할 확장입니다.

외부 ChatGPT의 [일정·코스 관리 연결](agent-api.md)은 별도 기능입니다. 외부 연결 키나 OAuth 토큰을 내부 AI에 전달하지 않습니다.

공식 참고: [REST 설정](https://developers.cloudflare.com/workers-ai/get-started/rest-api/), [모델](https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/), [무료 한도](https://developers.cloudflare.com/workers-ai/platform/pricing/).

일일 무료 제공량 소진 오류(3036)와 일시적인 처리 용량 부족(3040)을 구분해 안내합니다. 앱의 호출 횟수 카운터는 Cloudflare의 정확한 Neuron 사용량이나 남은 무료량을 뜻하지 않습니다.

### 내 대화

위투 AI의 코스 초안 아래 대화 내역에서 본인이 작성한 대화를 열어 이어갈 수 있습니다. 새 대화는 기존 기록을 삭제하지 않습니다. 성공한 질문·답변·코스 제안과 지침 버전을 저장하며 다른 계정과 외부 일정 도우미에는 공개하지 않습니다. 최근 100개 대화와 대화별 최근 50개 응답을 먼저 불러오며, 이전 대화 버튼으로 앞부분을 조회합니다. 새로고침하면 최근 대화를 복원합니다. 실패한 요청은 성공 기록에 추가하지 않습니다. 도입 전에 저장되지 않은 대화는 복구되지 않습니다.


## 프롬프트 변경과 버전 관리

서버 패키지의 `prompts/manifest.json`이 활성 버전과 정적 지침 묶음의 SHA256을 지정합니다. 버전 디렉터리에는 `system.txt`, `finish.txt`, `repair.txt`가 있으며 Git과 API 이미지에 함께 포함됩니다. 서버 시작 때 한 번 검증하고 메모리에 로드하므로 대화마다 DB나 파일을 조회하지 않습니다. 누락·해시 불일치가 있는 이미지는 시작하지 않습니다.

지침을 바꾸려면 기존 버전 디렉터리를 복사해 새로운 날짜/버전 이름으로 만들고 파일을 수정합니다. 이전 버전의 파일은 덮어쓰지 않습니다. manifest의 버전과 해시를 갱신하고 회귀 시험·wheel/이미지 검증 후 API 이미지를 배포합니다. 해시는 세 파일의 CRLF를 LF로 정규화하고, 키가 `system`, `finish`, `repair`인 JSON을 `ensure_ascii=False, sort_keys=True, separators=(",", ":")`로 직렬화한 UTF-8 바이트의 SHA256입니다. 공백·마지막 개행도 내용에 포함됩니다. 되돌릴 때는 검증된 이전 이미지 전체로 복귀합니다.

새 성공 응답과 작성자 전용 대화 결과에는 `prompt_version`, `prompt_sha256`이 저장됩니다. 이전 대화를 다시 조회해도 당시 버전을 유지하며, 과거에 저장하지 않은 해시는 빈 값으로 남습니다. 예전 버전 표기만 있는 기록은 정확한 지침을 식별하려면 당시 코드 revision도 필요합니다. 이 식별자는 정적 지침만 대상으로 하며 도구 규격·대화 입력·모델 출력을 포함하지 않습니다. 동일 버전이 동일한 답변을 보장하지는 않습니다. 프롬프트 원문을 제공하는 사용자 화면이나 조회 API는 없습니다.

도구 권한·입력 검증·사용량 한도·사용자별 자료 접근은 코드/DB에서 강제합니다. 프롬프트 수정만으로 접근 권한을 늘릴 수 없습니다. 외부 ChatGPT의 도구 설명·OAuth 규격은 내부 모델 지침과 별도로 관리됩니다.


## 실행 최적화와 운영 확인

모델·도구·대화 저장은 취소 가능한 비동기 요청으로 실행합니다. 프로세스가 소유한 작은 연결 풀은 소켓만 재사용하고 사용자 JWT·공급자 키·쿠키를 계정 사이에 공유하지 않습니다. 전체 작업 예산과 각 외부 호출 제한은 응답 본문을 천천히 받는 경우에도 적용합니다. 연결을 닫아도 이미 공급자가 처리한 추론 비용이나 전송한 DB 커밋까지 되돌릴 수는 없습니다. 통신 단절 후에는 같은 요청 ID로 결과를 확인합니다.

SQL040은 기존 대화 조회/저장을 유지하면서 추론용 작은 현재 조건·제안 조회와 정확한 요청 재조회, 처리 중 중복을 막는 임대를 추가합니다. 기존 SQL039 다음에 적용한 후 새 API를 배포합니다. 완성 기록은 기존 버전 충돌 검사를 거쳐 저장하며, 실패/임대 만료 뒤 다시 시도할 수 있습니다. 예전 버전에 반환된 응답을 현재 지침으로 다시 생성하지 않습니다. 미완료 임대는 성공/실패 또는 다음 요청의 만료 정리로 삭제되며 대화 원문을 별도 복제하지 않습니다. 성공 기록에는 요청 지문만 추가합니다.

같은 단계의 독립 읽기는 최대 두 개씩 실행하고 결과는 원래 요청 순서대로 반영합니다. 검색 주소를 이용한 후속 검색은 다음 단계에서 실행합니다. 선택한 저장 장소는 테이블별로 묶어 읽지만 조회 범위는 선택한 ID와 기존 사용자 권한으로 제한됩니다. 정상 코스에 모델의 사전 검사 왕복을 요구하지 않고, 서버의 최종 검사 결과를 표시합니다. 필수 정보가 비어 있으면 자동으로 사실을 만들지 않습니다.

모델 입력은 현재 조건의 미정·0원·제외·검색 범위·장소 참조를 유지하면서 빈 제어 상태와 중복된 목적지 문자열을 줄입니다. 현재 제안에서 비어 있는 기본 필드는 생략하며 서버 원본과 저장 계약은 그대로 유지합니다. 모델이 필요 없는 수정·취소에는 모델용 대화 구성도 생략합니다. 최종 스키마의 정적 정의는 시작 때 한 번 준비하고, 날짜·활동 수 제한은 요청별 복사본에 적용합니다. 사용자 대화·업무 자료나 인증 결과를 계정 간에 캐시하지 않습니다.

운영 로그의 `ai_run`은 단계별 시간·전송 바이트·모델/도구 횟수·공급자가 제공한 토큰 수·지침 버전·완료 상태만 기록합니다. 입력/답변 원문·주소·계정/대화/요청 ID·토큰 값은 넣지 않습니다. 같은 서버의 기존 회전 로그를 사용하며 외부 로그 서비스는 추가하지 않습니다. 토큰 수가 없거나 캐시 항목이 없으면 추정해서 채우지 않습니다.

외부 ChatGPT에는 필요한 정의만 남긴 정적 input/output schema를 제공합니다. 공개 도구 metadata만 시작 시 준비하며 인증 결과나 업무 자료를 전역 캐시하지 않습니다. 구조 결과와 JSON 텍스트의 병행 반환은 기존 MCP 클라이언트 호환을 위해 유지합니다. 내부 AI의 프롬프트·연결 키를 외부 도구 metadata에 섞지 않습니다.


## 복합 수정·코스 확인

현재 코스에서 “첫 번째와 두 번째 활동 순서 바꿔줘”, “전체를 30분 미뤄줘”, “1번과 3번을 15분 당겨줘”처럼 명확한 대상을 지정할 수 있습니다. 순서 교환은 활동의 장소·메모·시간을 함께 보존하고 목록의 위치만 바꿉니다. 여러 활동의 시간을 한 시각으로 설정할 수도 있습니다. 나머지 항목은 유지하며 사용자가 저장 버튼을 눌러야 업무 자료에 반영됩니다.

대상·이동량이 불분명하면 필요한 내용을 확인하고 같은 대화에서 이어 처리합니다. 미정 시간을 기준으로 이동하거나 자정을 넘겨 날짜를 바꾸는 요청은 확인 후 진행합니다. 날짜·예산 등 여러 항목 중 확인이 필요한 값이 있으면 변경을 보류하고, 답변 후 함께 반영합니다. 새 대화와 다른 요청에 보류된 편집을 자동 적용하지 않습니다. 활동 변경과 제목·날짜·예산 변경을 섞은 일부 복잡한 문장은 먼저 변경 범위를 확인합니다.

입력된 활동비 합계가 전체 예산을 초과하거나 여러 활동의 시각이 같으면 확인 사항으로 표시합니다. 미입력 비용·시간은 선택사항으로 유지합니다. 이 검사는 실제 가격·체류시간·이동시간이나 영업 정보를 계산하는 기능이 아닙니다. 검색 후보는 이번에 검색·조회한 항목이며 기존 코스의 장소를 새 검색 결과로 대신 표시하지 않습니다.

## 합성 평가와 운영 집계

API의 `tests/fixtures/ai_dialogue_cases.json`, `ai_dialogue_regressions.json`, `ai_upgrade_cases.json`, `ai_intake_cases.json`, `ai_efficiency_cases.json`은 실제 사용자 기록이 아닌 고정 합성 사례입니다. 기본 테스트는 외부 AI를 호출하지 않습니다. 운영자가 실제 모델 평가를 별도로 실행할 때에는 같은 모델·사례·제어된 검색/가상 상태·실행 예산으로 비교합니다. `tests/dialogue_evaluation.py`의 `evaluate`는 평가 프로세스 전용이며 서비스 프로세스에서 실행하지 않습니다. 평가의 검색·저장은 가상이며 모델 호출에는 공급자 제공량이 사용됩니다.

같은 사례의 보고서 두 개를 비교하는 명령은 다음과 같습니다. 불완전한 실행·다른 모델/사례는 비교를 거부하고, 후보의 실패가 하나라도 있으면 종료 코드가 실패합니다. 합성 사례 통과를 모든 한국어 표현의 정확도로 해석하지 않습니다.

```powershell
uv run --project apps/api python apps/api/tests/ai_evaluation_report.py before.json after.json
# 품질 통과와 함께 입력 토큰 10% 이상 감소·모델/도구 호출 증가 없음 검사
uv run --project apps/api python apps/api/tests/ai_evaluation_report.py before.json after.json --min-input-reduction-percent 10
```

비교 보고서는 모델이 실행된 요청의 응답시간을 따로 표시합니다. 입력 토큰 감소는 전후 모두 성공한 동일 요청에서 공급자가 보고한 사용량으로 계산하며, 누락 값을 추정하지 않습니다. 더 작은 입력이 모든 요청의 응답시간 단축이나 일정한 무료 사용 횟수를 보장하지는 않습니다.

서버 패키지의 `python -m we2day_api.ai_metrics`는 표준입력으로 받은 기존 `ai_run` 로그에서 버전별 성공·오류 범주, 응답시간 p50/p95, 모델/도구 호출·보고된 토큰과 검색 지표를 집계합니다. 대화 원문·주소·식별자·알 수 없는 필드를 출력하지 않습니다. 최대 10만 줄·32개 버전으로 처리량을 제한하고 누락 지표의 관측 수를 별도로 표시합니다. 검색 지표는 실제 상위 API 호출의 성공·실패·빈 목록과 받은 후보 수이며, 영업 사실이나 추천 품질의 점수는 아닙니다. 토큰 수는 공급자가 보고한 값이고 무료 Neuron 잔량은 아닙니다. 권한 있는 운영자가 필요한 기간의 기존 회전 로그를 입력하며, 새로운 외부 로그 서비스나 상시 원문 수집은 추가하지 않습니다.

현재 운영 모니터를 함께 갱신하면 기존 예약 점검 때 현재 API 컨테이너의 최근 24시간·최대 1만 줄의 AI 집계를 보호된 상태 보고서에 포함합니다. 집계가 불가능한 이전 API 이미지로 복귀해도 기존 건강 검사는 계속 실행하며 AI 집계만 unavailable로 표시합니다. 별도 외부 분석 서비스와 신규 예약 작업은 필요하지 않습니다.

컨테이너를 교체하면 이전 컨테이너의 로그가 사라질 수 있으므로 배포 전에 숫자 집계를 따로 남겨 전후를 비교합니다. 운영 환경은 교체 직전 집계와 최신 상태 보고서를 각각 보호된 파일로 유지하며 대화 원문을 복제하지 않습니다.

기존 코스에 따옴표로 명시한 장소를 추가하는 간단한 요청은 서버가 정확 이름으로 직접 조회합니다. 새 장소가 한 곳으로 확인됐을 때만 기존 활동을 보존해 추가하고, 여러 후보·검색 실패·기존에 포함된 장소는 확인을 받습니다. 추가 시간·비용 등 조건이 있는 요청은 기존 대화 처리와 검증을 거칩니다.
